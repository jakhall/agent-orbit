# Orbit rules, paths and gotchas in full

The long form of `.agents/project/discovery.md`, which keeps one line per rule and points here. Moved verbatim on 2026-11-13 (A6, E-64/X-4) so discovery stays under 10 KB; edit the rule here and its one-line summary there together.

## Commands in full

- Fastest check: `"%APPDATA%\Claude\claude-code\<version>\<hash>\claude.exe" plugin validate .` with the newest desktop CLI build: the highest version folder under `%APPDATA%\Claude\claude-code\` (2026-11-13: `2.1.321\d0e23af87588`). The desktop app updates it; the terminal `claude` is older, so do not use it.
- Before handoff: the same binary with `plugin test .` (kit: only `*.test.ts(x)`), `node --test "tests/server/*.test.mjs"` (server modules split out of `server.mjs` into `companion/lib/`; the kit ignores `.mjs`; Node 24 needs the glob, not the folder), `node tools/approve-hook-check.mjs` (the approval hook against scratch data, with timings), `node companion/smoke-test.mjs` (pop-out server API in `--dry-run` on a temp folder, and every module `/inbox/main.js` imports is served), `node --check` on `companion/inbox/*.js`, `shared/*.js`, `companion/*.mjs`, `hooks/*.mjs`, `tools/*.mjs` (the page modules are not type-checked), plus `node tools/typecheck.mjs`.
- Type-check: `node tools/typecheck.mjs [--dts <claude-code.d.ts>] [--tsc <typescript/bin/tsc>] [--out <dir outside the repo>]`. It writes a tsconfig to `%TEMP%\orbit-typecheck\<repo folder>-<hash>` (one per worktree, so parallel runs do not collide) covering `hooks`, `src`, `shared`, `types`, `tests` (minus `hooks/approve.mjs` and `tests/server`) and runs tsc, then a second pass over the page modules (`companion/inbox`; the old page's `companion/app.js` and `companion/js` left the checks with C9) with the DOM lib that reports only undefined names (TS2304/TS2552); either failing exits 1. Defaults: the newest `claude-code.d.ts` the plugin-authoring skill wrote under `%TEMP%\claude\bundled-skills\` (load that skill once in any session if none exists; never write under `~/.claude/dev-mods` for this) and TypeScript from `--tsc`, `ORBIT_TSC` (the environment or a git-ignored `.env`), the repo's `node_modules` or a global npm install. Baseline 2026-11-12 @ `29844e2`: 0 errors. The repo's own `tsconfig.json` extends `.claude-plugin/types/tsconfig.json`, which exists only after the engine has loaded the mod from a watched folder.
- End-to-end check of a session's own mod delivering replies: `node tools/e2e-replies.mjs [--auth-only] [--scratch <dir>]` starts a throwaway `claude.exe -p` session against a `--dry-run` server on a scratch folder (`ORBIT_DATA_DIR`; never `CLAUDE_CONFIG_DIR`, which once created a second `.claude.json` inside the real `~\.claude`). It seeds a session record with `replyProtocol: 2` (a `-p` session does not publish), arms replies, sends through `/api/reply` only, checks command refusals at the server, and checks that a file written into `inbox/` is deleted with an alert and never delivered. Not run by the gate; on the release check list as "run once" (it starts a real `claude.exe -p`).
- Pop-out by hand, safely: `node companion/server.mjs --serve --dry-run --data <scratch dir>` (records `claude://` launches at `GET /api/dry-run`, opens no window; refuses to run without `--data`; `--projects <dir>`, accepted only with `--dry-run`, points `/api/conversation` at test transcripts). Other modes: `--launch` (what the mod runs), `--prune`, `--clear` (never against the real data folder while testing).

## Local rules in full

- Observer hooks always call `next(e)`, return its result unchanged and carry `.catch(($, e, next) => next(e))` so they fail open.
- Publish only redacted facts: tool names, file basenames, program names, hostnames. Never prompts, outputs, arguments, assignments, search patterns or environment values; strip credentials from remote URLs.
- Positions depend on identity and age, never on status; never add continuous physics. The pane may re-pack whole clusters for its shape, never move nodes inside one.
- Statuses carry `Evidence` (source, confidence, observedAt); never present an inferred state or a context percentage as observed without a source.
- Bump the `shape` tag of an atom (one place: `SHAPES` in `src/state.ts`; a test checks every declaration) and the `schema` of a file when its meaning changes. Adding optional fields is not a meaning change: readers must tolerate their absence (`normalizeSnapshot`; `?? null` on records), because older sessions keep running.
- Design contract: `DESIGN.md` (repo root, contract since B2, 2026-11-13). Colours come from `PALETTE` (dark) and `PALETTE_LIGHT` in `shared/constants.js` only; the page applies light under `prefers-color-scheme` or the window's Theme setting, and the map's inline colours go through `paletteVars` (`shared/render.js`, used by `companion/inbox/map-view.js`). Status colour lives only in dots (amber needs you, green done or ready for review, accent working, coral failed, dim stale/unknown); text is neutral; the accent marks interaction and heading icons; no eyebrow (U-03 dropped). Four type steps (`--fs-meta/body/title/head` 11/13/15/18), two radii (`--r-control` 4, `--r-panel` 8), a 4 px spacing scale. Every control and status has a text name; tooltips may add detail. CSS lives in `companion/inbox/*.css` by region, imported in order by `companion/app.css` (order matters).
- Progressive disclosure: anything not needed at a glance is collapsed by default and remembered (pop-out `orbit.open` in localStorage, pane `PaneUi.openSections`). Standard actions are icon buttons with a tooltip and aria-label (`iconButton`); text labels only where an icon would be ambiguous.
- UI copy stays short: no explanatory footnotes where a tooltip (`title`) or the README can carry it. Detail rows with nothing to say are dropped; secondary rows are `isMore` (behind "More details").
- Conversation privacy (1.8): the pop-out's Conversation and reply line deliberately show prompt and reply text, but only in the local, token-protected pop-out, on request (section opened, or details of a session that needs you), read from the transcript tail by the server, held in the window's memory only: never persisted, logged, notified or published. Tool calls in it go through the shared categoriser; tool results and thinking are never returned. Slash commands show as `/name args` (args ≤ 300 characters) and their local output (`local-command-stdout`/`stderr`, colour codes stripped) as a Claude row. Keep `/api/conversation` keyed by a session in the current snapshot (never a path from the client), reading byte windows only (tail 512 KiB doubled while too sparse, `before=`/`from=` pages; ≤ 4 MiB per request, never the whole file), bound to the file by `fid` (409 on mismatch) and capped (≤ 30 rows per tail/page, ≤ 8,000 chars). The chat draws markdown with text nodes only (`shared/markdown.js`, never innerHTML, no links or images); with *Conversation text* off it fetches nothing (1.13). The desktop's suggested next prompt follows the same rules: read from the desktop record on request (`/api/suggestion`), held in the window's memory, shown only with Conversation text on; the snapshot carries only `hasSuggestion`.
- Replies as me: off unless the `replies` capability is armed (A5), pop-out only, always behind a control naming the route and the session (the chat's composer label, "To <session> · as you"; Enter sends, no review step: the owner's decision, 2026-11-10). Replies are the one message route (notes dropped, X-2): the pane has no message box, and with replies off or a session whose record lacks `replyProtocol: 2` the composer's place says why. The server holds each reply in memory; only the addressed session's own mod fetches it (control token), claims it with the server before submitting, delivers it only within 60 s, only once, never text starting with `!` or `#`, nor `/` unless it is a slash command the session itself listed and not on the deny-list (after stripping invisible characters and NFKC; such a command is run with `$.command.run` once the session is idle, never submitted or steered), and acknowledges it. No reply text is written to any file, snapshot, record, log, prefs or Diagnostics, which carry counts, times and a known refusal reason only. Never deliver twice rests on the claim: a withdrawal before the claim wins; after it, the acknowledgement decides, and anything not proven withdrawn is `unknown`, which the page never treats as safe to resend. A file written into `inbox/` is never read: the server deletes it and raises an alert.
- Git and gh (1.10): run only by absolute path (`findToolExe` in `server.mjs`: the standard install folder, else `where.exe $PATH:<name>.exe` from System32, rejected when inside a session folder; misses not cached), argv arrays, no shell, `windowsHide`, capped output, inherited `GIT_*` env stripped. Git: at most 2 processes at once, process tree killed (`taskkill /T /F`) after 4 s; always `--no-optional-locks -c core.fsmonitor=false -c core.untrackedCache=false`, env `GIT_OPTIONAL_LOCKS=0 GIT_TERMINAL_PROMPT=0 GIT_PAGER=cat GIT_NO_LAZY_FETCH=1`; repository-local filter drivers neutralised (`-c filter.<n>.clean=` etc., found with `git config --show-scope --get-regexp`); `--ignore-submodules=all`; diffs `--no-ext-diff --no-textconv --no-color`; never fetch; refuse (`network`) a gitfile/commondir/alternates on a network share before any git process. The folder comes only from the snapshot session matched by key (`normalizeFolder`). `gh`: only URLs passing `isPrUrl`, only while a pop-out window is connected, `GH_PROMPT_DISABLED=1 GH_NO_UPDATE_NOTIFIER=1 NO_COLOR=1`, 10 s; missing/signed out/rate limited backs off 10 min. Never run `gh` against real PRs in tests: `--dry-run` reads `<data>/pr-fixtures.json`. Edited paths and PR links are never logged.
- Maybe stuck (1.10) is an inferred hint, never a status: no dot, notification or Needs you. Two rules (repeat with failures, 4 of 6 failing), both needing the latest call to have failed; the "no progress" rule was dropped. Retune `STUCK` in `shared/aggregate/infer.js` only against real data: `node tools/stuck-replay.mjs [days]` replays the real `stuckOf` read-only over this machine's transcripts and prints how many turns each rule flags.
- *PR problems need you* is per window: it must never write shared prefs (hidden release reads `state.baseSnapshot`), never relabel running or waiting sessions, and notifications are keyed by session + need (`noticeKey`).
- Approvals and questions: the hook (`hooks/approve.mjs`) must fail safe and trust no file. It reads only `companion.json` for the server's port and control token, posts every prompt to `POST /api/hook/requests` with a nonce it keeps (a text-free marker when it cannot be shown), and engages only when the server says so (capability armed, an attentive window, a known session); then it long-polls for the answer. No server, a refusal, any doubt, exception or signal → no output, exit 0 → Claude's dialog. Always drain stdin. Only `{ behavior: 'allow' }` or `{ behavior: 'deny', message }`: never `updatedPermissions`, never allow a truncated (> 16 KiB) input, and `updatedInput` only for an `AskUserQuestion` answer (`questionOutput` from an answer `checkQuestionAnswer` accepted). Answers live in the server's memory, bind to id, input hash and nonce, are handed over once, and end when the request expires (60 s; a question can be kept open while someone types, up to 110 s, below the hook's 120 s timeout) or its window goes. Tool input and answers are never logged or written to files; the audit record keeps tool name, input hash and outcome only. Page decisions (arming, seen-to-end, hidden characters, outcomes) live in `shared/approvals.js` with tests. Never type invisible characters into source: build them with `String.fromCodePoint`.
- Launching sessions (1.12): only `wt.exe` (found with `lstat`: an App Execution Alias) + the newest desktop-bundled `claude.exe` that `Get-AuthenticodeSignature` says is validly signed by Anthropic; argv arrays; flags from `shared/launch.js` allow-lists (Ask = `manual`; the CLI rejects `default`); folder = the real path (`realpathSync.native`) through `launchFolder`; never the prompt on a command line (first prompt = a 1.9 inbox request written once `sessions/<uuid>.json` appears, errors caught); env = `launchEnv` allow-list only. A first prompt or `bypassPermissions` needs `replies` armed (`409 reason: 'not-armed'`), like a reply. Orbit never trusts a folder and never writes `~/.claude.json` (Trust from Orbit dropped, X-9, 2026-11-12): Claude asks in the new terminal; `GET /api/folder` answers only `{ folder, real, launchable, digest }` (digest = sha256 of the real path) and the launch must send that `digest`. Never spawn `wt.exe`/`claude.exe` while testing: `--dry-run` records `spawns`.
- Never create real desktop sessions or open Edge windows while testing: use the kit's `process.run` mock (argv assertions) or the server's `--dry-run`.

## Gotchas in full

- `claude plugin validate` refuses `$` passed anywhere but to plain `function` declarations (no class methods, arrow-function parameters, `$` in objects, `export const alias = fn`).
- Every `atom(...)` must be declared in the file that calls `read`/`update` on it; importing atoms is refused.
- PowerShell 5.1 `Set-Content -Encoding utf8` writes a BOM, which breaks `plugin.json`/`hooks.json`.
- The Bash tool on this machine collapses backslashes inside heredocs and `node -e` strings: write files holding Windows paths or regexes with the Write tool.
- Test kit: seed `state.get` only while the kit's own value is at version 0 and let `state.set` reach the kit; answering both yourself stops redraws. The kit's `$` has no `fs`: test modules that take `$` through hooks (e.g. `$.session.start`), not by calling them directly.
- Run system tools by full path (`paths.system32` in the mod, `SYSTEM32` in the server) with a working folder outside the session's project: bare `where.exe node` or `reg.exe` would search the session's folder first.
- Debug signals and flows (Diagnostics, `/api/health`, `snapshot-v2.json` `sources`, render cost in `publisher.pane` and `companion.json` `window`, `companion.log`, `audit.jsonl`, `/api/dry-run`): `.agents/project/observability.md`.
- Pop-out DOM (1.8): building the details content re-parents a reused node (the conversation) out of the live panel, so measure the panel's scroll before building, not just before `replaceChildren`; `requestAnimationFrame` never fires while the page is not drawn (hidden Browser pane, minimised window), so never gate input on it; scroll events and `IntersectionObserver` do not fire then either, so the chat measures its scroll before each redraw (`measureChat`) and Allow stays off in an undrawn window (on 2026-11-12 a Browser pane reported as hidden did deliver frames and resize callbacks, so test rather than assume); items inside a closed `<details>` still report layout boxes (`offsetParent`, rects), so filter by `details:not([open])` (the side panel's arrow order comes from `sideOrder` and the remembered open state instead); a line starting with `(` after a call continues that call (no semicolons in this codebase).
- The page is `GET /inbox` → `companion/inbox.html`; its modules come from `GET /inbox/<name>` (`companion/inbox/`, names matching `^[a-z0-9-]+\.(js|css)$`, no allow-list, no subfolders) and `GET /shared/<name>` (only names in `SHARED_FILES` in `server.mjs`: add a shared module there, or the smoke test's import crawl from `/inbox/main.js` fails). `GET /` redirects to `/inbox` (C9); the old page's routes (`/app.js`, `/app.css`, `/js/*`) are gone. One server per data folder: `--serve` takes `server.lock` (exclusive create, pid; a dead pid's lock is taken over) and a second server hands over to the live one and exits. Keep decisions in `shared/popout.js` (tested) and DOM work in the page.
- The pane: desktop draws every `Button` (even `plain`) as a native button, so each one adds chrome; prefer fewer buttons over more labels.
- Pop-out details panel: above 1280 px it takes a grid column (the stage shrinks by its width when it opens); at or below 1280 px it overlays the stage (`position: absolute`, z-index 3). `select()` and `rebuild()` draw the graph before `renderDetail()`, so anything placed from graph coordinates must be re-placed after the details render; a `ResizeObserver` alone is not enough because its callbacks, like rAF, do not run while the page is not drawn.
- Pop-out: read `innerWidth` lazily, it is 0 while the Browser pane is hidden.
- Pop-out layout: every `.layout` child has an explicit `grid-column`; hiding one (the side panel hides in list view and under 900 px) must not let the others shift into its column.
- Records are re-redacted on read (`cleanRecord` in `redact.ts`): tighten redaction there as well as in the publisher, or old records keep the old rules. The categoriser itself is `shared/redact.js` (since 1.8, also used by the server's Conversation), so a rule change there reaches publisher, re-redaction and Conversation at once.
- Per-viewer pop-out state the pane ignores: `hidden` (hide until active) and `expanded` (show all sub-agents of a session, past the cap, time window and completed filter); the pane's `visibleOf` call passes neither.
- The pop-out server prefers port 47821 (stable origin for its localStorage and notification permission); `--dry-run` always takes a random port.
- The test kit answers nothing beneath the plugins for `$.session.measure`: a test that raises it must also `on('session.measure', ...)`.
- `$.fs` has no delete: files the mod must "remove" are rewritten (actions) or left to the server's prune.
- Desktop sessions do not hot-reload mods; changes reach new sessions only, so old and new mod versions coexist (hence the legacy folder reads). Diagnostics' "Still on Agent Constellation" line counts them; remove the legacy reads (N3) once it stays at 0.
- Desktop `latestUserFrameAt > lastTurnEdgeAt` is not a reliable open-turn signal: `lastTurnEdgeAt` moves at a turn's start as well as its end, and continuations, replies, queued messages and notifications never move `latestUserFrameAt` (checked 2026-11-07 on a session mid-turn: frame 2,053 s old, edge 629 s old). Sessions with no live Orbit publisher (started before Orbit loaded, or terminal) therefore read as idle mid-turn. Since 1.9.1 the aggregator also reads the transcript's mtime (`withTranscriptActivity`, inferred evidence); since 1.13.1 a write past the edge only opens a turn when the last `user`/`assistant` entry (`lastEntryAt` in `shared/conversation.js`) is past it too, because an exiting CLI appends `last-prompt`, `cost-state` and system lines long after its last turn. The mod's `$.fs` has no ranged read, so that check reads the whole file (≤ 4 MiB, else falls back to the mtime), only when the mtime rule fires, cached per file mtime and size.
- Mixed versions: the on-disk launcher replaces only an older running server, never a newer one, and a mod never starts an on-disk server older than itself (a rollback): see `docs/CONTRACT.md` "The snapshot (schema 2)".
- The pane's `Svg` source is capped at 131,072 characters (compact markup holds about 480 nodes).
- Undocumented inputs can change with app updates: desktop session JSON, `waiting-input/`, subagent `.meta.json`, the `claude://claude.ai/epitaxy/` link. Diagnostics shows each source's health. The `claude://code/new` link is documented, but its Windows `folder` form is not.
