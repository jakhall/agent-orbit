# Orbit

A Claude Code mod for the Claude desktop app on Windows. One pane, and an optional pop-out window, over every local Claude session:

- **Needs you** first: questions, permission prompts, blocked and failed sessions, with how long each has waited. A session waiting on you is always counted, whatever the filters.
- **Pinned**, **Working**, **Ready for review**, **Just finished** (a turn ended in the last half hour) and **Recent** groups, in the pane list and the pop-out.
- **Time in state** ("Running 8m", "Needs permission 12m"), **cost so far** per session and the account's **rate limits** as small meters in the header ("5h 63%" over a bar, a dot from 80%), where the sessions report them.
- **Same checkout**: when two active sessions work in the same folder (not just the same repository), each says so ("⇄ same checkout as 1 other active session"); its details name the other.
- **Live status** of each session and its subagents: lifecycle (running, waiting for you, waiting for permission, idle, completed, interrupted, failed, stale, disconnected, unknown) and, separately, workflow phase (planning, researching, implementing, testing, reviewing, debugging, merging, …). Every status shows where it came from, whether it was observed or inferred, and how fresh it is.
- **Constellation graph**: projects as hexagon anchors, sessions around them, subagents as satellites, worktrees and PRs as optional supporting nodes. Stable, deterministic layout; drag nodes in the pop-out and the positions persist.
- **Conversation view** (the left list, the open conversation in the centre, its details on the right), **session, subagent and project drill-down**, **filters** (time window, project, model, state, phase, multi-word search, completed/stale toggles).
- **Open Session**: one click switches the desktop app to that exact existing session. It never creates one.
- **New session**: pick a recent project folder (or type one), a model, effort and permission mode, and an optional first prompt. Orbit (1.12) starts it in a terminal window itself (Claude asks there whether to trust a new folder), or choose Claude desktop to open its new-session page as before.
- **Pop-out window**: the full interactive graph in its own window, live-synchronised with the pane.
- **Message a session** (pop-out only): replies are the one way Orbit sends anything to a session. The pane has no message box.
- **Replies as me** (pop-out, off by default, all windows): Settings → *Replies as me* turns on the chat's composer, which sends your message into the session as you, as if typed there. It needs that session's Orbit to support reply protocol 2. With the setting off, or for a session without it, the composer's place says why, with *Turn on in Settings* or *Open in Claude*.
- **Remote control is off unless you arm it**: three switches in Settings, **Approvals**, **Questions** and **Replies as me**, all off by default and shared by every Orbit window. The server holds them (in `arm.json`, with a check value so a hand edit arms nothing). While any is on, the pop-out's Settings button carries a blue dot and its tooltip names what is on ("Settings · Remote control on: Approvals, Questions"; a click opens Settings at that switch), and the pane shows a "Remote control on, all windows:" indicator.
- **Approve and answer from Orbit** (pop-out, needs the **Approvals** and **Questions** switches): while you are using an Orbit window, permission prompts from sessions it shows wait there first, with the whole call to read (hidden characters shown as codes), **Allow**, **Deny** or **Answer in Claude**; after 60 s, or when you look away, Claude asks as usual. Questions Claude asks you (its multiple-choice cards) wait there too, but only while an Orbit window is in front when Claude asks; otherwise the question goes to Claude, and the chat says so with an **Open in Claude** button (2.1.6), as a card in the composer's place (1.15.1: tabbed like the desktop): one tab per question, named by its header and ticked once answered, plus a **Submit** tab; a single question has no tabs. Each question shows its options as radio buttons (one answer) or checkboxes (any), an *Other* choice with your own text, an option's preview in a monospace box when you focus or pick it, and *Add a note*. Picking an option of a one-answer question moves to the next tab; checkboxes and Other wait for **Next** (with **Back** after the first tab). Left/Right/Home/End move between tabs. The Submit tab reviews every answer (and note) with *Edit* links and flags what is missing; **Send answers** there turns on once every question has an answer (the line under it says what is missing); no key sends them, only the button. **Answer in Claude** (in the card's header, and on the Submit tab) hands the question back to the desktop. Your choices stay while the window redraws, only in the window's memory. It needs a one-time hook in your Claude settings (see Approvals below), which talks to the Orbit server.
- **Review what a session did** (pop-out, 1.10): **Changes** lists the files changed in its checkout (lines added and removed, untracked files, ahead/behind), the ones it edited first; linked **pull requests** show their checks and review state as a dot; a running session whose last calls keep failing says **Maybe stuck** and why.
- **Session manager** (pop-out): **chat** with a session without switching to it (its conversation under its details, scroll up for earlier messages, type at the bottom), **go to** any session with `Ctrl+K`, move through sessions with **`j`/`k`**, **hide** a quiet session until it is active again, and see **unread** sessions (state changed or a turn finished since you last looked) in bold.

Everything stays on this machine. Nothing is uploaded.

## Requirements

- Windows 10 or 11.
- Claude desktop with Claude Code 2.1.317 or later.
- Node.js 22 or later on `PATH` (the Orbit server and the pop-out window).
- Microsoft Edge (the pop-out window; Orbit never opens it in another browser).

## Install

In any Claude Code session (the desktop app's Code tab, or `claude` in a terminal), run:

```
/plugin install orbit --marketplace jakhall/agent-orbit
```

On an older Claude Code, add the marketplace first, then install:

```
/plugin marketplace add jakhall/agent-orbit
/plugin install orbit@agent-orbit
```

From a terminal the same works as `claude plugin marketplace add jakhall/agent-orbit` and `claude plugin install orbit@agent-orbit`.

- Start a **new** session: the Orbit pane opens by itself. Mods are not hot-reloaded, so sessions already open keep running without it.
- Update: `/plugin marketplace update agent-orbit`, then `/plugin update orbit`, then start new sessions. Old and new versions can run side by side for a while; that is expected.
- Orbit is off by default for anything that acts on a session: replies, approvals and questions each have their own switch in Settings (see "Remote control is off unless you arm it" above).

### Run from a clone instead

To try a local checkout (for example while developing), point `CLAUDE_CODE_PLUGIN_DIRS` in `%USERPROFILE%\.claude\settings.json` at the folder, and keep only one copy of Orbit loaded (uninstall the marketplace copy first):

```json
{
  "env": {
    "CLAUDE_CODE_PLUGIN_DIRS": "C:\\path\\to\\agent-orbit"
  }
}
```

New sessions load the folder as it is, so an edit there reaches every new session. `tools/refresh-live.ps1` keeps a separate frozen copy (`~\.claude\mods\constellation-live`) that is refreshed only after every check passes; point the variable there instead to keep work in progress away from your sessions.

## Use

- The **Orbit** pane opens by itself in every desktop session. Elsewhere, run `/orbit`.
- `/orbit graph`, `/orbit list`, `/orbit new`, `/orbit diag` open the pane on that view; `/orbit popout` opens the pop-out window.
- **Pane layout**: one line of counts, then **List · Graph · + (new session) · ↗ (pop out) · ⋯ (filters and settings)**. Filters live in Settings; while any filter hides sessions, one line says so with **Clear**.
- **List**: each row is two lines (title; state, project, age, activity). Press a row to open that session; `›` opens its details. Groups: Needs you, Pinned, Working, Ready for review, Just finished, Recent. *Pin* (in a session's details or on the graph card) keeps a session at the top whatever the filters.
- The pane's header names a rate-limit window only once it passes 80%; Diagnostics lists them all with reset times. The pop-out header shows them from 50%.
- **Constellation** (in the pane): a docked pane packs the project clusters to fit its shape and labels only what matters at that size (projects, sessions that need you or are running, the selection); hover a node for details; zoom, fit and focus with the buttons; pick a node with **Inspect** (when zoomed in, it is centred). In a docked pane the Needs you list above the graph shows three rows.
- **New session**: the header button, `/orbit new`, or *New session here* on a project or session. Choose a recent folder or type an absolute local path (`C:\repos\app`).
  - **Where: Orbit (terminal)** (pop-out, 1.12, the default): pick **Model** (from Orbit's list plus any model a recent session used), **Effort** and **Mode** (Ask, Accept edits, Plan, Auto; Bypass permissions needs a second tick and is never remembered). *Start* opens a Windows Terminal window running the Claude Code that ships with Claude desktop (checked to be signed by Anthropic); if Claude has not trusted the folder yet, it asks there, as it always does. The drawer closes and *Starting…* shows in the side panel and the status bar until the session reports in ("Not started yet · check the terminal" after a minute). It is selected then, unless you are typing or picked something else meanwhile. A first prompt is sent as your first message once the session is up (never on a command line; it cannot start with `/`, `!` or `#`), and the status says whether it arrived. A first prompt or Bypass permissions needs **Replies as me** on in Settings; the New session drawer offers the switch.
  - **Where: Claude desktop**: Claude shows its new-session page with the folder and prompt filled in, asks you to confirm the folder, and sends nothing until you press Enter there. The button reads *Open in Claude*; afterwards the drawer and the status bar say the prompt was handed over and is not started yet, and the prompt stays in the box. Orbit cannot start a desktop session by itself, and Claude may not come to the front (switch to it). The pane always uses this route.
- **Pane keys** (while the pane has focus): `l` list, `g` graph, `n` new session, `p` pop out, `s` settings and filters, `f` fit, `o` open the session shown in Details, `1`–`9` the sessions that need you (List: open in Claude; constellation: show their details).
- **Pop out**: drag to pan, wheel to zoom, click to select, drag a node to move it (children follow), double-click a project to focus it or a session to open it. Hovering a node shows a card with its state, project, branch, model, context, cost, turns and subagents. A selected session gets a small vertical quick menu beside it, on the side away from its label (below or above it near an edge): *Hide session* (until it is active again; greyed out while it needs you) and *Show all sub-agents* / *Show fewer sub-agents* (every sub-agent of that session, whatever the time window, completed filter or per-session limit; remembered per window; greyed out when it has none). Both items are always there; hover a greyed one for why. If opening the details panel would cover the selected node or push it off the graph, the graph pans it back into view.
- **Sub-agents and the time window**: a sub-agent shows while running or waiting, or when its last transcript entry falls inside the time window. Reopening an old session rewrites its sub-agent transcripts; Orbit ignores those rewrites (1.15), so they do not come back. On the graph a sub-agent's centre dot shows its state like a session's (green once completed). A session whose own turn has ended while its sub-agents still run shows as running ("2 sub-agents running"), not idle or ready for review, and counts in the header's *running*; the header's *sub-agents* is how many sub-agents are running.
- **"+N" pills**: a node with hidden children carries a "+N" pill on its upper right: subagents past the per-session limit (Settings → Subagents per session) or a collapsed session or project. Click the pill to show them (the pane shows the pill; expand from the pop-out). A session's details also offer *All in graph* / *Fewer in graph* and *Hide in graph*.
- **Pop-out panels**: drag the inner edge of the side panel or the details panel to resize it (arrow keys when focused, double-click to reset); widths are remembered.
- **Pop-out details**: status and actions (Open, pin, new session here, hide) first, then four facts as icons (project, branch, model, time) and what it is doing; everything else is in collapsed sections. A session with a transcript splits the panel: details on top (their own scroll), the chat below, with a splitter between them (drag it, or focus it and use the arrows, Page Up/Down, Home/End; double-click resets; the height is remembered). Standard buttons are icons; hover one for its name.
- **Pop-out keys**: `Ctrl+K` or `/` go to a session, `j`/`k` next/previous session (also `↓`/`↑` while the graph or the list has focus; in the side panel they step through its open groups), `Enter` on the graph, a list row or a side-panel item opens its details and moves focus into them, `o` open the selected session in Claude, `r` reply (focus the chat's composer), `n` new session, `p` pin the selected session, `g` graph, `l` conversation view, `f` fit, `+`/`-` zoom, `1`–`9` the sessions that need you (numbered in the list and the side panel: the list opens them in Claude, the graph selects them), `Esc` closes the switcher or the open drawer (one at a time) or the details (in a text field it just leaves the field). `j`/`k` follow the list order (Needs you first) and the details follow the selection. Settings → *Single-key shortcuts* turns the single keys (letters, digits, `/`) off; `Ctrl+K`, `Enter` and the arrows stay. A held key acts once (arrows repeat, throttled). The window title shows how many sessions need you, so the taskbar does too.
- **Go to a session** (`Ctrl+K`): one box over every session in the snapshot, each with its status dot, project and branch. Typing ranks by title, project and branch: whole words before letters-in-order matches; Needs you first within each (and first of all with an empty box). Sessions the current filters leave out are tagged *Filtered* (their details offer *Clear filters*); hidden ones come last, muted, tagged *Hidden*, and choosing one unhides it. `↑`/`↓` move, `Enter` shows the session (details, centred on the graph), `Ctrl+Enter` opens it in Claude, `Esc` closes. A status line under the list counts the matches.
- **Chat** (pop-out, 1.13; tidied in 1.14; its own pane in 1.15): the session's conversation, newest at the bottom, in a pane of its own under the details: the splitter is a full-width rule with a grip, and the chat's content and scrollbar line up with the details above. Its header bar ("Conversation", own background, stays put while you scroll) counts the prompts: "N prompts" once the whole conversation is loaded, "N+ prompts" while earlier pages are not. Claude's turns start with the Claude icon, its name and time, once per turn (a new header after 10 minutes, a question, or a new day; hover a message for its time); your prompts are blue-tinted cards with a person icon and their time underneath. Turns are 20 px apart, messages within a turn 10 px, tool lines 6 px, and a divider line ("Today", "Yesterday", "Mon 9 Nov") marks each change of day. While you scroll, the prompt that started the turn in view stays pinned at the top of the list (person icon, its first lines, its time) whenever its own row is out of view; at the end of a long turn that is your latest prompt. Click it (or Enter/Space) to scroll back to that prompt, which flashes briefly. It follows new messages while you are at the end; scrolled up, a *N new messages* button appears instead (*Jump to latest* when the newest messages were pushed out). Scrolling near the top loads earlier messages page by page back to "Start of this conversation" (the window holds up to 500 rows). Claude's replies show a safe subset of formatting (code blocks with a copy button, inline code, lists, tables, bold, italic, headings as bold lines; links and HTML stay plain text); long ones are clamped to about 10 lines with *Show more* (only those fade at the bottom), and a reply over 8,000 characters says where it was cut. Messages the app itself injects (updates from sessions you started, CI monitor updates, messages from other sessions) show as one muted line with an info icon, not as yours. A question Claude asked you shows in its own box, its options as a list with the recommended one in bold. Tool calls show as one muted line per run ("Edited auth.ts, ran tests · 4 tools"); tool output and thinking are never shown. While the session runs, the last line says "Claude is working · <what it is doing>" next to a pulsing dot (steady with reduced motion). Replies arrive when the transcript line is written, not token by token. If it cannot load, it says why and offers Retry.
- **Composer** (bottom of the chat, with *Replies as me* on): it says "Reply as you", and while it has focus a hint under it repeats the route and the keys; screen readers hear "To <session> · as you". Enter sends, Shift+Enter starts a new line; there is no review step. A permission request and what the session needs (one line) sit just above it; Allow arms only once the end of the request's input has been on screen. A message you send shows at once at the end of the chat with its delivery state, and goes once the transcript shows it. One message at a time. Outcomes: "Sent as you.", "Queued as you: sends when the session is idle." (mid-turn). After 15 s without an answer it says "Not delivered yet: the session may be closed." with *Keep waiting* and *Withdraw and edit*; after a minute it has expired and only *Edit* remains; both put the text back in the composer only once the reply is safely withdrawn. If Orbit cannot tell whether it arrived, it says "May have arrived. Check the session." and offers *Copy text*, never a resend. Replies starting with `/`, `!` or `#` (also behind invisible characters or look-alikes) are refused: those would run a slash command, a shell command or a memory shortcut. A reply in flight keeps its outcome when you select another session; when it ends there, the status bar keeps the outcome with *Show* until you dismiss it. A reply cannot answer a question dialog or approve a permission: open the session for those. An ended session's chat is read only, and so is a desktop session whose process Claude desktop stopped while idle: a short line in the composer's place says "Asleep. Wake it from Claude desktop to reply here." (the full sentence is in its tooltip).
- **Changes** (pop-out details, collapsed, 1.10): the session's checkout compared with its last commit (staged and unstaged), each file with `+added −removed` (`bin` for binary files), split into *Edited by this session* (from its transcript, subagents included) and *Other changes*, the first 20 shown with *Show all*; the branch and how far it is ahead of or behind its upstream (`2 ahead · 1 behind`, `no upstream`). *Untracked* files and files it edited *Outside this checkout* (grouped by checkout; temp, scratchpad, session memory and plan files only counted) are nested sections, closed until you open them. The heading counts it: `5 files · +1,120 −30`, `No changes`, `Not a git checkout`. Read when you open the section and again on refresh while it stays open and the window is visible (at most every 10 s).
- **Pull requests** (pop-out, 1.10): while the pop-out window is open, the server asks the GitHub CLI (`gh`, signed in on this machine) about PRs linked to sessions active in the last 7 days (at most 30; open ones every 2 minutes, merged or closed ones hourly; a re-run that passed replaces the failure before it). A session's *Pull requests* rows show a dot and `Repo #n`, with the state on a second line (`Checks failing: build, lint +2`, `Changes requested`, `Merged`, `Status unavailable`): coral checks failing, amber changes requested, blue checks running, green passing, approved or merged (not drafts). Graph PR nodes get the same dot. A list row's hint adds `Checks failing on #181` for the newest session linking that PR. Without `gh`, signed out or rate limited, it waits 10 minutes; the status bar's tooltip, the PR rows and the pane's Diagnostics say why. Settings → *PR problems need you* (off by default, this window only) adds the newest quiet session linking such a PR (not running or waiting, active in the last day, not hidden) to Needs you ("Checks failing on #123") with the usual notification rules, without changing its state or unread mark.
- **Maybe stuck** (1.10): a running session whose latest calls keep failing says so, muted, under its state, in the hover card and in its list hint: `Same call 3 times, 2 failed: Edit app.py` or `4 of the last 6 calls failed`. It clears once a call succeeds. It is an inferred hint, never a status: no dot, notification or Needs you entry, and only sessions running Orbit (which publish their tool calls) can show it.
- **Hide until active**: the moon icon in a session's details takes a quiet session out of Orbit's list, graph and side panel until it has new activity or needs you, then it comes back by itself (one that comes back because it needs you stays back). The status bar shows "N hidden · Show" (counting only sessions your filters would show) to bring them all back. Nothing in Claude changes; sessions that need you cannot be hidden.
- **Unread**: a session's title is bold (list, side panel, switcher) when its state changed or a turn finished since you last opened its details, and it is not running; opening them clears it. Ordinary activity while it runs does not count. Remembered per window; nothing is marked on the first run.
- **Pop-out banner and status bar**: the status bar says **Live** while a Claude desktop session running Orbit keeps the data fresh, and when it was last updated. When something is wrong a banner over the view says what, with one action: not live (no desktop session with Orbit running: *New session in Claude*), not updated for a while (sending pauses and status dots go grey), updates paused (*Resume*), reconnecting or unreachable (*Retry*), this window's link expired after Orbit restarted (use *Pop out* in the Orbit pane), a snapshot this window cannot read, or no sessions yet. While any remote-control switch is on, a blue dot on the Settings button says so, and its tooltip names the switches. An alerts banner says when Orbit deleted a file it did not write (a forged approval or reply file) or when the arm settings failed their check (everything is then off).
- **Pop-out side panel** (graph view): Needs you, Pinned, Ready for review and Just finished. The list view is grouped the same way as the pane's, with the side panel hidden. The header's "N need you" jumps to the list.
- Colour: text is neutral and headings carry a small blue icon. Status colour is only a dot: amber needs you, green complete or ready for review, blue running, coral failed. A session that needs you is labelled by what it needs, not by its lifecycle.
- Drill-down: the surface shows only what you need at a glance; Changes, Subagents, Activity, Pull requests and Details (folder, context, cost, turns, IDs, status sources) are collapsed sections that remember being opened. The pop-out side panel groups collapse the same way (Needs you and Pinned start open).
- **Notifications**: raised by the Orbit server, once per need. By default a session that starts needing you or fails raises one; the *All* mode adds sessions ready for review, and *Off* mutes them. None is raised for a need that began over 5 minutes before the server saw it, or more than one per session a minute. An open Orbit window shows them: a silent Windows notification while you are elsewhere (allow it once in Settings), a banner at the top-right while you are looking, with a soft two-note chime for Needs you (Settings → *Play a chime*, per window). With no Orbit window open, a terminal session's Orbit raises them on its own channel. The title is "Needs you · <session title>" (or "Failed", "Ready for review") and the body is the status line. Diagnostics shows what was raised and, if one did not show, why.

## Approvals

To let the pop-out answer permission prompts and questions, add a user-level hook to `%USERPROFILE%\.claude\settings.json` (keep a backup), then turn on the **Approvals** and **Questions** switches in Settings in the pop-out:

```json
"hooks": {
  "PermissionRequest": [
    { "matcher": "*", "hooks": [{ "type": "command", "command": "\"C:/Program Files/nodejs/node.exe\" \"<Orbit folder>/hooks/approve.mjs\"", "timeout": 120 }] }
  ]
}
```

`<Orbit folder>` is where Orbit is installed, with forward slashes. A marketplace install lives under `C:/Users/<you>/.claude/plugins/cache/agent-orbit/orbit/<version>/`, so the path changes with each update: point the hook at the new version after updating (an old path that no longer exists only means Claude asks as usual). A clone is its own folder.

The hook talks to the Orbit server with the control token in `companion.json`; it reads no request or answer files. Nothing engages unless the matching switch is on, an Orbit window is in use (focused, or used a moment ago) and the session is one Orbit lists; otherwise the hook exits at once and Claude asks as usual. Prompts and questions from sessions Orbit does not list, plans and the app's own cards always go to Claude. Recommended: deny Claude's file tools access to `~/.claude/orbit/**` and to Orbit's own folder (`~/.claude/plugins/cache/agent-orbit/**` for a marketplace install) in `permissions.deny`. Remove the hook entry to uninstall.

## Settings

Pop-out, for all windows (held by the server, all off by default): the **Approvals**, **Questions** and **Replies as me** switches. The notification mode (All, Needs you, Off) is the server's too.

Pop-out only, per window: single-key shortcuts, conversation text, PR problems need you.

Shared by the pane and the pop-out window: animation (pop-out only, **Off** by default, which suits remote desktop and machines without a GPU; the pane's graph never animates), refresh interval (5–60 s), sessions kept, subagents shown per session, stale threshold, PR nodes, simplified graph, pause live updates, reset layout, clear stored data, diagnostics.

## Privacy

- All data lives in `%USERPROFILE%\.claude\orbit\`. Nothing leaves the machine.
- Session records hold tool names, file **basenames**, program names (`npm test`, `git commit`), hostnames, statuses and timestamps. Never prompts, tool output, command arguments, assignments or variables, search patterns, file contents or environment values. A remote URL loses any embedded credentials before it is stored.
- **The chat** is the one place Orbit shows prompt and reply text: only in the pop-out window, only for the session whose details you have open, read from that session's transcript (`~\.claude\projects\…\<session id>.jsonl`) by the local, token-protected server: the end first (the last 512 KB, widened step by step up to 4 MB when that holds too few turns), then earlier pages only as you scroll up, never more than 4 MB per request and never the whole file. It is kept in the window's memory only (at most 500 rows per session, 12 sessions): never written to Orbit's files, the log, notifications or anything published. Tool calls in it are reduced to the same redacted words as the records; tool output and thinking are dropped. Formatting is drawn as plain text nodes, never as HTML. Settings → *Conversation text* off hides the messages and fetches nothing (turn it off when sharing your screen); the chat shrinks to its composer, which still works.
- **Changes** runs Git (by its full path: `%ProgramFiles%\Git\cmd\git.exe`, else the one on `PATH`, never one inside a session's folder) only in the session's own folder from the snapshot, with read-only questions (`rev-parse`, `symbolic-ref`, `status`, `diff --numstat`, `rev-list --count`): never a fetch or lazy fetch, no locks, no fsmonitor, hooks, external diff, text conversion or filter driver from the repository's own config, at most two at a time, each ended after 4 seconds. A repository whose Git data sits on a network share is not read at all (Git itself still opens a share named in the repository config's `include.path`). The file list and the session's edited paths (only the paths of Edit, Write, MultiEdit and NotebookEdit calls in its transcript) stay in the pop-out window; nothing is stored or logged.
- **Pull requests**: only links of the form `https://github.com/<owner>/<repo>/pull/<n>` reach `gh` (`gh pr view <link> --json …`, no shell, prompts and update checks off, 10-second limit, two at a time), and only while a pop-out window is open. Statuses are kept in the server's memory; failing check names are shown, nothing else from the PR.
- Records are re-redacted whenever Orbit reads them, so anything recorded under weaker rules is reduced to what Orbit publishes before it is shown or saved.
- Cost figures are the list-price totals Claude Code reports per session (as `/cost` does), not a subscription bill.
- A first prompt typed into *New session* goes straight into the `claude://` link handed to Claude. It is not stored or logged by Orbit, but it is on that process's command line, which process-auditing tools on this machine can record.
- The Orbit server listens on `127.0.0.1` only and rejects other `Host` headers and cross-origin requests. It runs as a daemon that a session's Orbit starts, so no window is needed. Opening Pop out gives Edge a one-time launch code (60 seconds); the server answers with an HttpOnly `orbit` cookie, so no token is in the URL and a reload keeps the window. A code used twice means something read Edge's command line first: the cookie secret rotates, the window is locked out and an alert is raised; open Pop out again. `companion.json` holds only a control token, which reaches the hook and mod routes and nothing else. While no window is connected, the server refuses to send replies, start or open sessions, answer approvals, change the switches or clear data. It stops once no window has been connected and no session has changed for 30 minutes.
- **Replies as me** live in the server's memory, not in files. Only that session's own Orbit takes one, over the server (it claims it, so it is delivered once, then acknowledges), only within a minute, and never for text starting with `/`, `!` or `#`. Replies need that session's Orbit to support reply protocol 2 (otherwise Orbit says the session is older), and are refused while the *Replies as me* switch is off. The text is never put in the snapshot, the session records, logs or preferences; Diagnostics and the session's details show only counts, times and the last refusal reason. A reply has the same power as typing in that session, which is why the composer names the session and the route on its label before you press Enter.
- **Approve and answer from Orbit** runs a small script, `hooks\approve.mjs`, as a `PermissionRequest` hook from your Claude settings. It posts each prompt to the Orbit server and does nothing more (Claude's dialog appears as before, after about 0.1 s of Node start-up) unless the **Approvals** switch (**Questions** for a question) is on, an Orbit window is in use and the session is one Orbit lists. Then it waits up to 60 seconds for your answer. It only ever answers allow or deny for that one call, bound to its exact input, once, and only while it is still waiting; it never changes your permission rules or the call. A question is the one exception: it is answered by passing your chosen answers (and notes) back with the question's own input, which is how the desktop answers it; the answers are never logged. Allow works only once the whole call has been on screen and a second after it appeared; input too long to show in full can only be denied or sent to Claude. Whether or not Orbit engages, a prompt leaves a text-free marker so the session shows as Needs you. The hook reads no request or answer files; the server deletes any approval or reply file it finds, since it writes none, and raises an alert. Switch changes, approvals, questions, replies and alerts go to an append-only audit log (short fixed fields, never text), listed in Diagnostics. Anything running as you can still read `companion.json`, and with it the control token; deny rules for Claude's file tools on `~/.claude/orbit/**` are recommended, and tools that run code (Bash) can still reach them, as they can already do anything you can.
- **Starting sessions** (1.12): Orbit only ever runs `wt.exe` and the Anthropic-signed, desktop-bundled `claude.exe` with flags from fixed lists, in the real path of a folder you chose, with a minimal set of standard Windows environment variables (plus Orbit's plugin folder); the first prompt goes through the server's reply queue, not a command line. Orbit never writes `~/.claude.json`: trusting a folder is Claude's own prompt in the terminal. Anything that can read Orbit's token can start a session. The hook and the mod also check, on every call, that the server proves it holds that token, so a program that only takes over Orbit's port gets no answer through.
- **Settings → Clear stored data** deletes the session records, inbox, approvals and action files and the snapshots, and resets preferences. The server keeps running. The `--clear` command line option stops the server first and also removes `companion.json`, the log and the pop-out window's browser profile.

## Disable or uninstall

1. Disable: `/plugin disable orbit` (enable it again with `/plugin enable orbit`). New sessions pick it up.
2. Uninstall: `/plugin uninstall orbit`, and remove the `PermissionRequest` hook entry if you added it. A clone: remove the `CLAUDE_CODE_PLUGIN_DIRS` entry instead.
3. Optionally delete Orbit's data folder, `%USERPROFILE%\.claude\orbit\`.
4. The server stops on its own once no window has been connected and no session has changed for 30 minutes. A session's Orbit starts it again when needed.

From a clone, `tools/refresh-live.ps1` refreshes the frozen copy only after every check passes, keeps the previous one in `~\.claude\mods\constellation-prev`, and `-Rollback` puts it back.
